# Lab Vibes London

Interactive map of **aggregated, user-reported impressions** of research
laboratories and working environments at London universities and research
institutes. Recurring themes are summarised **locally** by an LLM from lawfully
collected public social-media discussion; the public site shows **only
sanitised summaries and aggregate statistics — never the raw dataset**.

The map uses one marker per verified campus or research location. A single
institution coordinate is not treated as a physical place: multi-campus
universities can span central, east and west London as well as hospital-based
research sites.

> Everything shown is an **unverified, user-reported perception, not a verified
> fact**. The project does not rank, score or make factual claims about
> individual researchers, and produces no "best/worst lab" lists.

- **London** is active. **Oxford** and **Cambridge** are designed for and shown
  as _coming later_.
- Institutions covered at launch: Imperial College London, University College
  London, King's College London, Queen Mary University of London, London School
  of Hygiene & Tropical Medicine, and The Francis Crick Institute.

See also [`DATA_GOVERNANCE.md`](DATA_GOVERNANCE.md) and the in-app
**Methodology** and **Ethics & limitations** pages.

## 1. Project purpose

Prospective students and researchers rely on scattered, anecdotal word of mouth
when choosing a group. This project gathers **public** discussion, summarises
recurring themes responsibly, and presents them as _perceptions_ with explicit
evidence and confidence indicators — so a reader gets context, not a verdict.

## 2. Architecture

GitHub Pages is static and cannot run a local LLM, so the project is split into
two cleanly separated halves that communicate only through **sanitised JSON**:

```
┌─────────────────────────────┐        sanitised, aggregated JSON        ┌────────────────────────┐
│  Local Python pipeline      │   ──────────────────────────────────▶   │  Static React website   │
│  (maintainer's machine)     │        web/public/data/*.json            │  (GitHub Pages)         │
│                             │                                          │                        │
│  import → anonymise →        │   raw text NEVER leaves this box         │  loads JSON, renders     │
│  moderate → aggregate →      │   (Ollama is local-only)                 │  map, panels, filters    │
│  summarise (Ollama) → export │                                          │                        │
└─────────────────────────────┘                                          └────────────────────────┘
```

```
acamap/
├── pipeline/                 # Python package: ingest, moderation, aggregation, LLM, export
├── tests/                    # pytest: unit + privacy-leak tests
├── data/
│   ├── institutions/         # committed catalogue (institutions.json, regions.json)
│   ├── samples/              # committed synthetic demo data (fictional)
│   ├── raw/                  # LOCAL ONLY — your lawfully collected posts (git-ignored)
│   ├── processed/            # LOCAL ONLY — anonymised working data (git-ignored)
│   ├── moderation/           # LOCAL ONLY — private withheld queue (git-ignored)
│   └── cache/                # LOCAL ONLY — LLM content-hash cache (git-ignored)
├── web/                      # React + TypeScript + Vite + Leaflet frontend
│   └── public/data/          # sanitised JSON consumed by the site (committed)
├── pyproject.toml            # Python project (uv)
└── .github/workflows/        # CI + GitHub Pages deployment
```

**Stack:** React, TypeScript, Vite, Leaflet + OpenStreetMap (CARTO tiles) ·
Python 3.12, Pydantic, pandas, Ollama · pytest, Vitest · GitHub Actions.

## 3. Installation

Prerequisites: **Python 3.12**, **Node 20+**, [**uv**](https://docs.astral.sh/uv/),
and (for real summaries) [**Ollama**](https://ollama.com).

```bash
# Python pipeline
uv sync --extra dev            # creates .venv and installs deps + test tools

# Frontend
cd web && npm install && cd ..

# Configuration
cp .env.example .env           # then edit .env (set a long random LABVIBES_HASH_SALT)
```

## 4. Ollama setup

Summaries are generated by a **local** model. Raw text is only ever sent to this
local endpoint — never to a cloud service, a GitHub Action or the browser.

```bash
# Install Ollama from https://ollama.com, then:
ollama pull qwen2.5:7b-instruct     # default model; handles Chinese + English
ollama serve                        # if not already running as a service
```

The model is configurable via the `LABVIBES_MODEL` environment variable (any
locally pulled model). The endpoint is `OLLAMA_HOST` (default
`http://localhost:11434`).

> **No Ollama? No problem.** Every pipeline command accepts `--offline`, which
> uses a deterministic, network-free heuristic summariser. The demo JSON shipped
> in `web/public/data/` was generated this way so the site works immediately.

## 5. Input-data format

Import **lawfully collected** public posts as CSV or JSON into `data/raw/`
(git-ignored). One row per post, comment, or engagement snapshot. Fields:

| Field | Required | Notes |
| --- | --- | --- |
| `source` | ✅ | e.g. `rednote` |
| `post_id` | ✅ | platform post id (hashed on import) |
| `comment_id` | | present ⇒ the row is a comment (hashed) |
| `author_id` | ✅ | hashed on import |
| `text` | ✅ | Chinese and/or English; never published |
| `posted_at` | ✅ | ISO-8601 |
| `collected_at` | ✅ | ISO-8601; enables longitudinal snapshots |
| `institution_id` | ✅ | must match a catalogue id (e.g. `imperial`) |
| `department` | | |
| `lab_name` | | |
| `campus_id` | | canonical catalogue id when the source provides it |
| `campus_name_raw` | | raw source wording, internal only and never exported |
| `campus_assignment_method` | | `provided`, `catalogue_match`, `inferred_from_lab`, or `unspecified` |
| `campus_assignment_confidence` | | optional `low`, `medium`, or `high` |
| `researcher_name` | | optional; internal entity resolution only, **never published** |
| `source_url` | | **discarded** on import |
| `likes_at_collection` | | integer |
| `comments_at_collection` | | integer |

**Longitudinal:** to record engagement over time, add more rows with the same
`post_id`/`comment_id` but a later `collected_at`; the pipeline merges them into
one item with multiple engagement snapshots.

### Location assignment (`campus_id` compatibility schema)

The committed catalogue gives every institution a display-only `map_center`
and a list of canonical `campuses`. Departments and labs declare
`campus_ids`; a lab may belong to several campuses without being duplicated in
institution totals. The public interface uses **Locations** as the umbrella
term, reserving **Campus** for sites officially described that way and using
**Institute** or **Research location** for the others.

Assignment is deliberately conservative:

1. A valid `campus_id` supplied by the import is recorded as `provided`.
2. Raw campus wording is matched only to one canonical name, short name or id
   (`catalogue_match`).
3. With no campus wording, assignment is inferred only when the matched lab
   has exactly one known campus (`inferred_from_lab`).
4. Every other item remains `campus_id: null` (`unspecified`). It appears under
   **Location unspecified** and never contributes to a location marker or
   location-specific summary.

Raw campus wording remains in the private processed artefact for audit but is
forbidden by both public-data privacy scanners. Location summaries and
multi-location lab/location summaries use the same minimum threshold of 5 items
from 3 authors. Institution-wide lab summaries may differ because they can
also include safely moderated location-unspecified evidence.

A ready-to-use fictional sample lives at `data/samples/synthetic_posts.csv`
(and `.json`). Regenerate it with `python data/samples/generate_synthetic.py`.
To add a new approved source type, implement a `SourceAdapter`
(`pipeline/adapters/base.py`) and register it in `pipeline/adapters/__init__.py`.

## 6. Running the pipeline

```bash
# 1. Validate a private CSV/JSON without writing artefacts
uv run python -m pipeline validate --input data/raw/private-pilot.csv

# 2. Import + anonymise (hashes ids, drops source URLs, merges snapshots)
uv run python -m pipeline ingest --input data/samples/synthetic_posts.csv

# 3. Moderate + aggregate + summarise with the local model
uv run python -m pipeline summarize
#   ...or without Ollama:
uv run python -m pipeline summarize --offline

# Useful flags:
uv run python -m pipeline summarize --dry-run   # plan only; no model calls, nothing written
uv run python -m pipeline summarize --force     # ignore the summary cache and regenerate
uv run python -m pipeline summarize --model qwen2.5:14b-instruct
```

(`uv run labvibes ...` is an equivalent console-script shortcut for
`uv run python -m pipeline ...`.)

The `summarize` step runs the moderation pass first, so sensitive content is
withheld **before** anything reaches the model.

## 7. Reviewing withheld content locally

The moderation queue is **private and git-ignored**. Review it locally:

```bash
uv run python -m pipeline review          # counts + reasons only
uv run python -m pipeline review --full   # also prints withheld text (local human review)
```

Treat this material as sensitive: it exists so a human can check the automated
moderation. Never publish or commit it.

## 8. Generating public JSON

```bash
uv run python -m pipeline export
```

This writes **only** sanitised, aggregated JSON to `web/public/data/`
(`institutions.json`, `regions.json`, `meta.json`). Every payload is run through
a privacy scan first; the export fails if any forbidden field (username,
author/profile id, raw text, unredacted URL) would be written.

## 11. Deploying to GitHub Pages

Deployment is automated by `.github/workflows/deploy.yml`, which builds **only**
the static site from committed sanitised JSON (the pipeline and raw text never
run in CI).

1. Push the repository to GitHub.
2. In **Settings → Pages**, set **Source: GitHub Actions**.
3. Push to `main` (or run the workflow manually). The site publishes at your
   Pages URL.

Vite derives `base` from `GITHUB_REPOSITORY` during Actions builds: project
Pages use `/<repository-name>/`, while an owner Pages repository uses `/`.
Public JSON is loaded through `import.meta.env.BASE_URL`. Routing uses
`HashRouter`, so deep links and refreshes work on Pages without a 404 fallback.

To publish updated summaries, run the pipeline locally, commit the regenerated
`web/public/data/*.json`, and push.

## 12. Adding Oxford or Cambridge later

No application changes are needed — the `region` field drives everything:

1. In `data/institutions/regions.json`, set the region's `"status"` to
   `"active"`.
2. In `data/institutions/institutions.json`, add institutions with
   `"region": "oxford"` (or `"cambridge"`), a display-only `map_center`, and
   verified campus records with official-name and coordinate provenance.
   Add `campus_ids` to every department and lab; do not collapse a collegiate
   or multi-site university to one physical marker.
3. Import data whose `institution_id` matches, then re-run
   `ingest → summarize → export`.
4. Commit the regenerated JSON. The region selector activates the new region and
   the map recentres automatically.

## 13. Ethical and methodological limitations

Read the in-app **Methodology** and **Ethics & limitations** pages and
[`DATA_GOVERNANCE.md`](DATA_GOVERNANCE.md). In short:

- Summaries are **unverified perceptions**, presented as such — never facts,
  rankings, or claims about named individuals.
- **Selection bias**, **unverifiable identities**, and **platform recommendation
  algorithms** limit interpretation; absence of comment is not evidence of
  absence of a problem.
- Publication requires **≥5 items from ≥3 authors**; otherwise the site shows
  _"Insufficient public data for a reliable summary."_
- Serious allegations, misconduct accusations, identifying medical information
  and targeted insults are **automatically withheld** to a private queue.
- Raw posts, comments, usernames, source URLs, moderation queues, LLM caches and
  environment files are **never committed** (enforced by `.gitignore` and tests).
- Ambiguous location wording is not forced onto a presumed main campus, appears
  publicly as **Location unspecified**, and is never included raw in public
  output.

## What still needs the repository owner

- Enable **GitHub Pages** (Settings → Pages → Source: GitHub Actions).
- Supply a **permitted dataset** in `data/raw/` for real (non-synthetic)
  summaries, and install/pull **Ollama** to generate them.
- Set a strong `LABVIBES_HASH_SALT` in `.env`.
